# Jumping Whale Fluid Demo

> Demo path: `lab/lite/src/demos/fluid/scenes/jumpingWhale.ts`

## Purpose

The Jumping whale demo exercises FLIP collision against a deforming skeletal mesh. The visual whale uses the glTF skin and `Whale_Breach_Jump` animation from `lab/public/jumping-whale/whale.glb`.

The initial ocean occupies world Y `0..7`. The whale asset uses a base placement plus a demo-level **Whale Y offset** slider (`-10..10`, default `-2`). The default starting pose and collision proxies are fully submerged, while the authored breach rises through the free surface.

The demo hides the shared presentation ground so only the ocean volume is visible. **Animation speed** scales the breach clip from `0.05x` to `3x`. **Collision velocity** multiplies the temporal boundary speed (`0x` disables velocity transfer, `1x` is physical animation speed). **Exact deforming SDF** switches between the interactive bone proxies and the baked skinned surface. **Show collision shapes** displays cyan ellipsoid rings in proxy mode and magenta zero-crossing crosses sampled from the same interpolated field used by collision in deforming-SDF mode.

**Stabilize initial state** is enabled by default for PBF, MLS-MPM, and PB-MPM. After reset, quality change, or JSON import, the visible render loop is suspended, the whale remains at animation frame zero, and the selected solver advances in hidden GPU batches using the current physics, grid, flow, and collision values. Representative particle blocks are sampled once per simulated second; two consecutive stable height distributions publish the equilibrium shape, with a 30-second simulated safety limit. Before publication, solver motion is cleared while preserving positions: PBF velocity, MLS velocity/affine state, or PB-MPM displacement/affine state. Playback then restarts from frame zero. Disabling the checkbox restores immediate reset behavior. FLIP skips this pre-roll because its incompressible pressure projection does not need it.

The shared **Quality** selector uses Jumping whale FLIP presets:

| Tier   | Particle capacity | Grid resolution | Markers per cell |
| ------ | ----------------: | --------------: | ---------------: |
| Low    |            40,000 |              80 |                4 |
| Middle |            80,000 |             100 |                8 |
| High   |           140,000 |             120 |               12 |

## Bone-Proxy Collision

The interactive implementation uses six local signed-distance grids associated with the whale skin joints:

- `Spine`
- `Fin.L`
- `Fin.R`
- `Head`
- `TailBase`
- `TailTip`

Each grid contains an ellipsoid fitted to vertices primarily weighted to that joint. Its center and extents are derived directly in the skin's authoritative joint bind space: each bind-pose vertex is assigned to its strongest `JOINTS_0` / `WEIGHTS_0` influence and transformed by that joint's `inverseBindMatrices` entry. Using the accessor directly is important because an exported skin's bind matrices need not be reconstructible from the node hierarchy alone. The grids are packed once by `createFluidCompositeSceneSdf`. Every frame, after evaluating the glTF animation, the demo derives each joint's current world matrix from the live skin matrix:

```text
jointWorld = currentMeshWorld * boneMatrix * inverse(inverseBindMatrix)
```

`updateFluidSceneSdfTransforms` publishes current and previous transforms. The composite SDF therefore supplies both collision distance and temporal boundary motion without reallocating buffers or rebuilding solver pipelines.

FLIP resolves marker velocity relative to the moving boundary's normal velocity. Bone-proxy collision does not model tangential friction or exact skin deformation between proxies.

## FLIP Fluids Comparison

FLIP Fluids handles a deforming obstacle as an animated triangle mesh:

1. Blender evaluates the complete modified/skinned mesh for every simulation frame.
2. Export writes one triangle mesh per frame.
3. The solver receives previous, current, and next meshes through `MeshObject.update_mesh_animated`.
4. The native simulation rebuilds the obstacle representation and derives object velocity from those frame meshes.

This is suitable for offline baking but too expensive for Babylon Lite's interactive frame loop.

## Exact Deforming-SDF Mode

The comparison mode uses `lab/public/jumping-whale/whale-sdf.bin`, generated by:

```powershell
pnpm exec tsx scripts/bake-jumping-whale-sdf.ts
```

The baker writes `whale-sdf.meta.json` with the source GLB SHA-256. Fluid demo builds compare that hash with `whale.glb` and automatically regenerate the SDF when the model changed before staging either asset. This belongs in the build workflow rather than the browser UI: a deployed web page cannot write generated repository assets.

The TypeScript baker parses the GLB directly and evaluates the same raw glTF translation, rotation, and scale samplers used by the runtime. It skins the body, dorsal fin, pectoral fins, and tail flukes with the asset's `JOINTS_0`, `WEIGHTS_0`, and inverse-bind matrices, then expresses each frame in the animated Spine joint's local space. The main body's boundary loops are triangulated from existing weighted vertices before baking so parity signing sees a closed solid.

`generateMeshSdf` bakes every frame into the same `49 × 66 × 30` grid at `0.25` unit spacing. Frames are stored as packed half floats; the replacement asset's complete 12-second clip produces 144 frames and a 26.65 MiB binary.

The binary is fetched lazily the first time **Exact deforming SDF** is enabled, so the normal Fluid demo startup and proxy mode do not pay its download or CPU-memory cost. `createFluidDeformingSceneSdf` keeps only the two adjacent frames in its GPU storage buffer. When the animation crosses a baked-frame boundary, the next pair is uploaded into the fixed atlas; no solver pipeline or GPU resource is recreated. The shader:

- trilinearly samples and blends the adjacent SDF frames using the visual animation clock;
- extrapolates that blend for `sceneSdf(point, dt)` so FLIP sees deforming-surface velocity;
- separately extrapolates the current/previous `Spine` world transforms for rigid motion;
- applies **Collision velocity** to both deformation and transform velocity without changing the current collision position.

Both collision modes use the same visual animation, fluid domain, camera, and rendering settings for direct comparison.

For MLS-MPM, both modes are intersected with the same invisible inset box used by Whiteboard. Its lower faces sit `2.5` cells inside the simulation grid and its upper faces sit `3.5` cells inside, placing the SDF wall half a cell before MLS-MPM's mandatory transfer-stencil clamp. Particles therefore collide with a normal separating wall instead of accumulating on clipped outer-grid edges. FLIP and PBF leave this numerical container disabled.

Jumping whale opts into temporal moving-boundary response for every solver:

- FLIP resolves marker velocity relative to the scaled boundary-normal velocity.
- MLS-MPM applies that relative response at inside grid nodes before G2P and again for penetrating particles.
- PBF ensures its collision position correction advances at least as far as the scaled outward boundary displacement; its normal velocity is then reconstructed from the corrected position.
- PB-MPM resolves both grid and particle displacement relative to the scaled moving boundary.

Static inset-container faces have zero temporal SDF velocity and retain their ordinary wall response.

## Assets

## Validation

Focused validation checks:

- the demo loads with no WebGPU errors;
- `Whale_Breach_Jump` loops;
- the live `Head` proxy transform changes over time;
- FLIP remains interactive with all six proxy grids enabled;
- Exact deforming SDF mode loads its two-frame packed atlas and follows the visual animation;
- switching between proxy and deforming-SDF collision rebinds the active solver without recreating it;
- switching away hides the whale and switching back resumes the animation.
